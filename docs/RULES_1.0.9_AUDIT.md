# 《赵云与阿斗》1.0.9 规则与数值证据审计

审计日期：2026-09-03；负责模块：01 规则与数值基线。

机器配置：`packages/shared/src/config.ts` → `RULES_CONFIG_1_0_9`；规则版本：`1.0.9`；配置结构版本：`1.0.0`。

## 1. 审计结论

现仓库可以证明“当前配置与仓库内候选取证稿的多数表格一致”，但不能独立重放原包取证。根目录候选稿记录了 Android 1.0.9 包名、XAPK SHA-256、解包数量和包体字段定位；仓库同时保留了 DCC 提取工具，但没有提交原 XAPK、DCC 清单、提取后的 JSON、配置类/方法摘录、实机操作录像或提取日志。

因此本审计使用三种状态：

- `package-recorded`：候选取证稿把该项标作包体值，且当前 Markdown/TypeScript 与表格一致；仍不等于仓库可独立重放。
- `pending-original-verification`：只有二手整理、存在冲突，或缺少足以确认精确算法/触发条件的原包片段。
- `project-adaptation`：原作广告/分享改为直接获得、10Hz 权威推进等本项目新增决策，不得标成原包规则。

发布冻结要求比 `package-recorded` 更高：必须补交最小、可审计且不包含无关版权资源的证据摘录，并让固定输入输出测试能够复算。

## 6. 版本化配置与消费者迁移

`RULES_CONFIG_1_0_9` 已把下列域统一挂到一个公开入口：

- `recruitment`：牌池、权重合计、早期账号加权、营地容量与回收规则；
- `merge`：同兵种升级与 12 组武将字关系；
- `attackRange`、`units`：命中几何、攻击/攻速/射程和等级倍率；
- `props.catalog/effects/acquisition`：原始道具表、结构化效果、获得情景与广告直接领取映射；
- `waves`、`maps`：波次、难度、Boss 概率和地图；
- `evidence/provenance`：来源、状态与证据定位。

为保持已有接口兼容，本轮没有删除 `GAME_CONFIG`、`TOKEN_POOL`、`SOLDIERS`、`GENERALS`、`PROPS` 等旧具名导出。以下跨模块接线需由对应任务完成：

1. 模块 02：把 `simulation.ts` 内道具概率、半径、持续、农民/铲子计时、武将技能与 Boss 系数硬编码改为读取版本化配置，并对待核验项建立禁发门槛。
2. 模块 03：单位检查器的跨侧攻速加成改读 `props.effects`；界面不得解释 `null` 待核字段。
3. 模块 05：战后金币、商品数、10% 广告商品、转盘与日重置改读 `props.acquisition`。
4. 模块 00/08：在 `rules-config`、`match-snapshot` 合同中增加 `rulesetVersion` 与 `rulesConfigSchemaVersion`，由集成任务写入快照/存档。旧快照缺省映射到当前兼容版本，移除旧入口另起主版本。

本轮未修改 `docs/contracts/`、`simulation.ts`、客户端、服务端、UI、联网、美术或生产配置，符合模块边界。

## 7. 最小证据补齐清单

不需要提交完整原包或美术资源。建议由合法持有者生成以下最小证据后再冻结：

1. 原 XAPK 的版本、包名、文件大小和 SHA-256 校验输出；
2. DCC 树清单（路径、对象 ID、SHA-1/大小）及 `extract-laya-dcc.cjs` 运行日志；
3. 仅包含相关配置行的脱敏 JSON/文本摘录：牌池、兵种、武将、波次、地图、道具；
4. 相关方法的最小控制流摘录或伪代码：`d.Si`、招贤榜、练兵符、补给触发、`ja`/`Ha` 调用链、陨石、行军丹、摸金校尉；
5. 对每个随机规则给出固定输入、随机值、预期输出，不只给统计结论；
6. 对广告获得情景给出逐步实机证据，明确首次、后续、满营地、跨日与刷新行为；
7. 生成证据清单哈希并由规则模块测试校验，证据变更必须提升配置结构版本或规则版本。

在这些材料到位前，`pending-original-verification` 项可以作为当前兼容实现继续开发，但不得在发布说明中宣称为 1.0.9 已验证冻结。
