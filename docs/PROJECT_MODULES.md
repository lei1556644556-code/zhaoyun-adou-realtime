# 《赵云与阿斗》正式项目模块划分

## 目标

将规则复刻、战斗模拟、界面交互、美术表现、账号存档、实时联机、质量验收和发布运维拆成可独立开发、测试和评审的模块。模块之间只依赖公开合同，避免在 `main.ts`、`BattleScene.ts` 或服务端入口中继续堆叠跨域逻辑。

## 任务与所有权

| 编号 | 模块 | 主要所有权 | 对外产物 |
|---|---|---|---|
| 00 | 项目总控与接口合同 | `AGENTS.md`、`docs/PROJECT_MODULES.md`、`docs/contracts/` | 架构边界、接口审批、集成顺序 |
| 01 | 规则与数值基线 | `docs/RULES_*`、`packages/shared/src/config*`、原包证据与提取工具 | 可追溯的规则/数值配置，不实现表现层 |
| 02 | 权威战斗内核 | `packages/shared/src/simulation*`、共享战斗测试 | 确定性命令、状态、快照、战斗事件 |
| 03 | 战场交互与跨端 UI | `apps/client/src/game/BattleScene*`、输入、布局和信息面板 | 拖放/点击/缩放/响应式交互，通过端口调用战斗层 |
| 04 | 美术资源与战斗表现 | `apps/client/public/assets/`、`apps/client/src/presentation/`、资源清单 | 字版/图片版皮肤、动画、特效、音画事件映射 |
| 05 | 账号经济与云存档 | `apps/client/src/auth/`、`apps/client/src/economy/`、`supabase/` | 登录、账号隔离、存档、奖励与道具持久化接口 |
| 06 | 实时联机与房间匹配 | `apps/client/src/net/`、`apps/server/` | 房间、匹配、断线重连、命令传输、权威快照同步 |
| 07 | 自动化测试与质量验收 | 各级测试、测试夹具、验收脚本与报告 | 原版规则回归、拖放回归、双端与双人链路验证 |
| 08 | 集成发布与线上运维 | 应用组合入口、`.github/workflows/`、部署配置、版本说明 | 模块接线、迁移、GitHub Pages/服务端发布和回滚 |

## 依赖方向

```text
规则与数值 ──> 共享接口 ──> 权威战斗内核
                         ├──> 战场交互 UI
                         ├──> 美术表现
                         └──> 实时联机服务端

账号/经济/存档 ──适配器──> 大厅与局外流程
测试验收 ────────────────> 验证全部模块
集成发布 ────────────────> 只负责组装公开接口和发布
```

禁止反向依赖：共享战斗内核不得导入 Phaser、DOM、Supabase 或 WebSocket；美术资源不得携带规则数值；客户端不得另写一套与服务端不同的战斗判定。

## 核心接口合同

接口的详细约定集中在 `docs/contracts/README.md`。第一阶段沿用并逐步收口现有公开类型：

- `GameCommand`：玩家唯一可提交的游戏意图；
- `CommandResult`：命令是否成功以及失败原因；
- `MatchSnapshot`：可持久化、可同步、可恢复的完整权威状态；
- 战斗事件流：攻击、受击、合成、升级、掉落、死亡、胜负等一次性表现事件；
- `MatchTransport`：本地人机与实时服务器可互换的传输适配器；
- `AccountStore` / `ProgressStore`：认证信息与游戏进度隔离；
- `AssetManifest`：棋子、武将、地图、UI、特效和音效的稳定资源键。

## 集成规则

1. 规则配置先合入，战斗内核再消费；任何临时默认值必须标记为未核实，不能进入发布版。
2. 战斗层先发稳定快照和事件，UI、表现与网络层再并行接入。
3. 跨模块变更以接口合同和契约测试为准，不以某个页面的临时实现为准。
4. 每个模块在独立工作树和任务中提交；08 模块按依赖顺序集成，发生冲突时不丢弃任何一侧业务逻辑。
5. 版本发布前必须由 07 模块执行桌面、手机、人机、房间对战、刷新恢复和断线重连验收。

## 完成定义

模块只有同时满足以下条件才算完成：职责内功能可运行、关键逻辑有测试、公开接口有文档、手机与电脑端不退化、没有复制权威数值、没有未说明的跨模块修改，并提供可复现的验证结果。
